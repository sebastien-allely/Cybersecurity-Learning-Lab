# Contribuer au projet

Merci de l'intérêt que vous portez à **Cybersecurity Learning Lab**.

L'objectif de ce projet est de proposer un référentiel pédagogique fiable, reproductible et maintenable autour de la cybersécurité défensive. Toute contribution est la bienvenue dès lors qu'elle respecte les principes définis dans le `PROJECT_CHARTER.md`.

---

# Avant de contribuer

Avant toute proposition, merci de consulter les documents suivants :

* `README.md`
* `PROJECT_CHARTER.md`
* `docs/00-Introduction/DOC-000-Writing-Guide.md`
* `SECURITY.md`
* `CODE_OF_CONDUCT.md`

Ils définissent la philosophie, les règles de rédaction et les exigences de qualité du projet.

---

# Types de contributions acceptées

Les contributions peuvent notamment porter sur :

* la correction d'erreurs techniques ;
* l'amélioration de la documentation ;
* l'ajout de références officielles pertinentes ;
* l'amélioration de scripts existants ;
* la correction de fautes d'orthographe ou de typographie ;
* la proposition de nouveaux laboratoires ou exercices ;
* l'amélioration des schémas d'architecture.

---

# Exigences de qualité

Toute contribution doit respecter les principes suivants :

* être techniquement vérifiée ;
* être reproductible ;
* être cohérente avec l'architecture de référence ;
* privilégier les sources officielles ;
* documenter les limites de la solution proposée ;
* conserver une approche pédagogique.

---

# Références

Les affirmations techniques doivent, dans la mesure du possible, s'appuyer sur :

* la documentation officielle des logiciels ;
* les publications de l'ANSSI ;
* les publications du NIST ;
* les recommandations de l'OWASP ;
* la matrice MITRE ATT&CK ;
* toute autre source reconnue et fiable.

Les contenus doivent être rédigés avec vos propres mots. Les citations doivent rester limitées et correctement attribuées.

---

# Scripts

Les scripts proposés doivent :

* être idempotents lorsque cela est possible ;
* être documentés ;
* être testés dans le laboratoire de référence ;
* comporter un en-tête homogène avec les autres scripts du projet.

---

# Documentation

Chaque nouveau document doit respecter la structure définie dans :

`docs/00-Introduction/DOC-000-Writing-Guide.md`

L'objectif est de conserver une documentation homogène sur l'ensemble du dépôt.

---

# Pull Requests

Avant d'ouvrir une Pull Request, vérifiez que :

* la modification répond à un besoin identifié ;
* le contenu a été relu ;
* les commandes ont été testées ;
* les références sont correctement citées ;
* la documentation est mise à jour si nécessaire.

Une Pull Request incomplète pourra être refusée jusqu'à correction.

---

# Philosophie

Cybersecurity Learning Lab privilégie la qualité à la quantité.

Une amélioration modeste, correctement documentée et testée, apporte davantage de valeur qu'une fonctionnalité importante insuffisamment validée.

Merci de contribuer à faire de ce projet une ressource fiable pour la communauté.
