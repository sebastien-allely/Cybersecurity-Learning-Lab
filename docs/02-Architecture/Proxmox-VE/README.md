## Architecture actuelle et architecture cible

Une distinction est maintenue entre :

**Architecture actuelle**

Elle correspond exclusivement aux composants réellement déployés et vérifiés dans le laboratoire.

**Architecture cible**

Elle décrit les évolutions envisagées mais qui ne sont pas encore nécessairement déployées.

Une évolution décrite dans la documentation ne doit donc pas être interprétée comme une fonctionnalité existante tant que celle-ci n'a pas été effectivement mise en œuvre.

---

## Principes documentaires

La documentation Proxmox suit les principes suivants :

* documenter l'architecture réellement déployée ;
* éviter les doublons entre référentiels ;
* distinguer les faits des évolutions envisagées ;
* identifier les dépendances critiques ;
* documenter les composants nécessaires à l'exploitation ;
* conserver les références utilisées pour les décisions techniques ;
* mettre à jour la documentation après toute évolution significative.
